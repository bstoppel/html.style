Project guidelines for html.style, a modern web-standards CSS framework that is simultaneously a component library, an HTML starter template, a design system, and a CSS methodology. States the core philosophy: modern standards with no polyfills, AI-friendly machine-readable architecture, "Platform Native Engineering" where semantic HTML maps to browser APIs, and delete-key friendliness. Names AI agents as the primary users by 2026, which is the stated reason machine-readability and predictability drive every decision.

Documents the repository layout (src/, dist/, docs/, tests/, website/) and the npm scripts for serving and for the Playwright suites (all, headed, UI, a11y, visual, performance).

Records the load-bearing technical decisions. Browser support is stated as hard floors — Chrome/Edge 131+, Firefox 133+, Safari 18+ — with container queries, OKLCH, light-dark(), cascade layers and relative color syntax assumed present. The file records why: the floor is set by FULL relative-color-syntax support, which the derived state tokens depend on (first support lands earlier but is partial), and it explicitly forbids restating the floor as a rolling version count, because engine cadences differ and Safari's numbering jumped 18 to 26 in 2025. All colors are OKLCH for perceptual uniformity, P3 gamut and programmable contrast. Cascade layers are declared in the fixed order reset, tokens, atoms, molecules, organisms, templates. Design tokens are three-tier: primitives (--p-*), semantic (--color-*, --space-*), and state derived through relative color syntax. Atomic design is interpreted strictly — atoms are bare semantic elements styled without classes (style <button>, not .btn), molecules are component classes using container queries, organisms are compositions. JavaScript is native-first ("if a browser can do it natively, delete the JavaScript"), TypeScript where JS is unavoidable, and reusable markup ships as native web components with a build step that inlines partials and a JS fallback when served from src/.

Prescribes patterns to follow — container queries over media queries, light-dark() theming, :focus-visible, WCAG AA contrast, prefers-reduced-motion, semantic landmarks — and Core Web Vitals targets of LCP < 2.5s, CLS < 0.1, INP < 200ms. Explicitly forbids BEM child classes, utility-first CSS, JavaScript for CSS-solvable problems, and appearance-based token names. Fallbacks are limited to a single preceding declaration; no @supports blocks or polyfills.

A "Files to Understand" section orients newcomers at README.md, src/css/, src/examples.html, dist/ and tests/README.md. Closes with git workflow: Conventional Commits, hyphenated description-only branch names, and a pre-commit checklist requiring a passing `npm test`, visual verification in the browser, no accessibility regressions, and no console errors.
