Contributor guide for html.style. Covers issue reporting (browser and OS versions, minimal reproduction, expected versus actual), feature suggestions judged against the project philosophy, and the fork/branch/test/PR flow.

Development guidelines restate the framework's house style in reviewable terms: .editorconfig settings (2 spaces, LF), semantic HTML, modern CSS features, minimal native-first JavaScript. The CSS section requires a hex fallback declaration immediately before every OKLCH color, the three-tier token prefixes (--p-* primitives, --color-*/--space-* semantic, relative-color-syntax state), the fixed @layer order, and flat component naming (.component-name, .component-name--variant) with the atoms layer styling elements directly and taking no classes. JavaScript must work without JS, use native APIs over libraries, feature-detect rather than sniff, respect Global Privacy Control, and ship as ES modules.

Accessibility is a merge condition, not an aspiration: WCAG AA 4.5:1 minimum, semantic elements before ARIA, keyboard and screen-reader testing. The pre-submission checklist is explicit about what is automated versus manual: `npm test` covers Chromium only (the single project in playwright.config.js), so Firefox and Safari must be verified by hand at or above the README's supported floors. It also requires both color schemes, several viewport sizes, container-query verification, axe/Lighthouse checks, and Core Web Vitals. Commits use Conventional Commits.

The philosophy section names six principles (semantic HTML first, container over media queries, OKLCH, native-first, AI-friendly, delete-key friendly) and then draws an unusually explicit acceptance boundary. Accepted: bug fixes, performance, accessibility, baseline-modern CSS adoption, docs, tests. Rejected outright: JavaScript library dependencies, non-OKLCH color formats, utility-class frameworks, build complexity without clear benefit, and anything duplicating a native browser capability.

The Questions section points to CLAUDE.md for detailed patterns and src/examples.html for component demonstrations; both resolve.
