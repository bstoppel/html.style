Documentation

Complete guide to html.style's design system, layout primitives, and components.

Design Tokens

html.style uses CSS custom properties (CSS variables) for all design tokens, enabling dynamic theming and easy customization.

No Build Step Required

All tokens are defined in CSS and work directly in the browser. No preprocessor or compilation needed.

Colors (OKLCH)

All colors use the OKLCH color space for perceptually uniform colors across light and dark modes.

Color System

/* Surface colors */
--color-surface-base      /* Main background */
--color-surface-elevated  /* Cards, modals */
--color-surface-sunken    /* Wells, inputs */

/* Text colors */
--color-text-primary      /* Body text */
--color-text-secondary    /* Muted text */
--color-text-inverse      /* Text on dark backgrounds */

/* Brand colors */
--color-brand-primary     /* Primary brand color */
--color-brand-secondary   /* Secondary brand color */

/* Semantic colors */
--color-feedback-success
--color-feedback-warning
--color-feedback-error
--color-feedback-info

/* Interactive colors */
--color-interactive-primary
--color-interactive-hover
--color-interactive-active

Why OKLCH?

  • Perceptually uniform - Equal changes in values produce equal perceptual changes
  • Wider color gamut - Access to more vibrant colors on modern displays
  • Easy theming - Adjust lightness for dark mode without changing hue
  • Better accessibility - More predictable contrast ratios

Custom Colors

Define your own colors in OKLCH format:

:root {
  /* oklch(lightness chroma hue) */
  --color-brand-primary: oklch(0.6 0.18 260);
  --color-brand-secondary: oklch(0.65 0.15 180);
}

[data-theme="dark"] {
  /* Increase lightness for dark mode */
  --color-brand-primary: oklch(0.7 0.2 260);
}

Spacing

Spacing uses a modular scale with T-shirt sizing for intuitive naming.

Spacing Scale

--p-space-xs:   0.25rem  /* 4px */
--p-space-sm:   0.5rem   /* 8px */
--space-component: 0.75rem  /* 12px */
--p-space-md:   1rem     /* 16px */
--p-space-lg:   1.5rem   /* 24px */
--p-space-xl:   2rem     /* 32px */
--p-space-2xl:  3rem     /* 48px */
--p-space-3xl:  4rem     /* 64px */
--space-inline: 1.5rem   /* Horizontal spacing */
--space-block:  1rem     /* Vertical spacing */

Fluid Spacing

Some spacing values use clamp() to scale between viewport sizes:

--space-inline: clamp(1rem, 5vw, 2rem);
--space-block: clamp(0.75rem, 3vw, 1.5rem);

Container Queries

All components use container queries instead of media queries, making them truly responsive to their container size.

How It Works

Components adapt based on their container width, not the viewport width:

.card {
  container-type: inline-size;
  container-name: card;
}

/* Component adapts to container width */
@container card (min-width: 30rem) {
  .card__content {
    display: grid;
    grid-template-columns: 1fr 2fr;
  }
}

Benefits

  • True component isolation - Components work anywhere
  • No breakpoint coupling - Components don't depend on viewport
  • Composable layouts - Nest components without conflicts
  • Better maintainability - Change layout without touching components

Layout Containers

The framework provides container breakpoints for common patterns:

/* Small container (< 30rem / 480px) */
@container (max-width: 30rem) { ... }

/* Medium container (30rem - 48rem) */
@container (min-width: 30rem) and (max-width: 48rem) { ... }

/* Large container (> 48rem / 768px) */
@container (min-width: 48rem) { ... }

Cascade Layers

html.style uses CSS Cascade Layers for predictable specificity and easy overrides.

Layer Order

@layer reset, tokens, layouts, components, utilities, overrides;
reset - CSS reset and normalization
tokens - Design tokens (colors, spacing, typography)
layouts - Layout primitives (Stack, Cluster, Grid, etc.)
components - UI components (Button, Card, Alert, etc.)
utilities - Utility classes
overrides - User customizations (highest priority)

Why Layers?

  • No specificity wars - Layer order trumps specificity
  • Easy overrides - User styles automatically win
  • Better organization - Clear separation of concerns
  • Future-proof - Add new styles without refactoring

Custom Overrides

Add your custom styles in the overrides layer:

@layer overrides {
  .button {
    /* Your custom button styles */
    border-radius: 2rem;
  }
}

Theming & Dark Mode

Automatic dark mode support with manual override capability.

Automatic Dark Mode

Respects user's system preference by default:

:root {
  color-scheme: light dark;
}

/* Light mode colors */
:root {
  --color-surface-base: oklch(0.98 0 0);
  --color-text-primary: oklch(0.15 0 0);
}

/* Dark mode colors */
@media (prefers-color-scheme: dark) {
  :root {
    --color-surface-base: oklch(0.15 0 0);
    --color-text-primary: oklch(0.98 0 0);
  }
}

Manual Toggle

Use the included JavaScript for manual theme switching:

import { ThemeManager } from './js/html.style.js';

// Toggle theme
ThemeManager.toggle();

// Set specific theme
ThemeManager.setTheme('dark');   // Force dark
ThemeManager.setTheme('light');  // Force light
ThemeManager.setTheme('auto');   // Follow system

Custom Themes

Create your own theme by overriding tokens:

/* Custom "ocean" theme */
[data-theme="ocean"] {
  --color-brand-primary: oklch(0.6 0.15 220);
  --color-surface-elevated: oklch(0.95 0.02 220);
  --color-interactive-primary: oklch(0.5 0.18 200);
}

Layout Primitives

Composable layout components based on Every Layout principles.

Stack

Vertical spacing between child elements:

<div class="stack">
  <div>Item 1</div>
  <div>Item 2</div>
  <div>Item 3</div>
</div>

/* Custom spacing */
<div class="stack" style="--space-block: 2rem;">...</div>

Cluster

Horizontal grouping with wrapping:

<div class="cluster">
  <button>Action 1</button>
  <button>Action 2</button>
  <button>Action 3</button>
</div>

/* Custom alignment */
<div class="cluster" style="justify-content: space-between;">...</div>

Sidebar

Sidebar layout with flexible content area:

<div class="sidebar-layout">
  <aside style="--sidebar-width: 16rem;">Sidebar</aside>
  <main>Content</main>
</div>

Grid

Responsive grid with automatic columns:

<div class="grid" style="--grid-min: 15rem;">
  <div>Card 1</div>
  <div>Card 2</div>
  <div>Card 3</div>
</div>

Center

Center content with max-width constraint:

<div class="center" style="--measure: 60rem;">
  <p>Centered content</p>
</div>

Switcher

Switch between horizontal and vertical layout:

<div class="switcher" style="--switcher-threshold: 30rem;">
  <div>Column 1</div>
  <div>Column 2</div>
</div>

Box

Consistent padding with optional border:

<div class="box">
  <p>Padded content</p>
</div>

<div class="box box--bordered">...</div>

Browser Support

html.style targets modern browsers with native support for latest web standards.

Minimum Versions

  • Chrome/Edge 105+ (September 2022)
  • Firefox 110+ (February 2023)
  • Safari 16.4+ (March 2023)

Required Features

  • Container Queries
  • Cascade Layers
  • OKLCH Color Space
  • CSS Nesting (optional enhancement)
  • :has() selector
  • dvh/svh viewport units

Progressive Enhancement

Core functionality works without JavaScript:

  • Theming respects system preference
  • Forms use native HTML5 validation
  • Dialogs use native <dialog> element
  • Responsive layouts use CSS only

Feature Detection

Use @supports for graceful degradation:

@supports (color: oklch(0 0 0)) {
  /* OKLCH colors supported */
}

@supports not (color: oklch(0 0 0)) {
  /* Fallback to RGB */
  --color-brand-primary: rgb(107, 70, 193);
}

Accessibility

html.style is built with accessibility as a core principle, targeting WCAG 2.1 AA compliance.

Semantic HTML

All components use appropriate semantic HTML:

  • <button> for interactive actions
  • <nav> for navigation regions
  • <main> for primary content
  • <article> for standalone content
  • <aside> for sidebar content
  • Proper heading hierarchy (h1-h6)

Keyboard Navigation

  • All interactive elements are keyboard accessible
  • Skip links for screen reader users
  • Focus visible indicators (WCAG 2.4.7)
  • Logical tab order
  • Escape key closes dialogs/modals

ARIA Attributes

Used sparingly, only when needed:

<div class="alert" role="alert">...</div>
<button aria-expanded="false" aria-controls="menu">Menu</button>
<nav aria-label="Main navigation">...</nav>

Color Contrast

All color combinations meet WCAG AA standards:

  • Normal text: 4.5:1 minimum contrast
  • Large text: 3:1 minimum contrast
  • Interactive elements: 3:1 against background

Motion

Respects user's motion preferences:

@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
  }
}

Testing

Automated accessibility testing with axe-core:

npm run test:a11y

Manual testing checklist:

  • Keyboard-only navigation
  • Screen reader testing (NVDA, JAWS, VoiceOver)
  • Color contrast verification
  • Zoom to 200% (WCAG 1.4.4)
  • Text spacing adjustments (WCAG 1.4.12)
